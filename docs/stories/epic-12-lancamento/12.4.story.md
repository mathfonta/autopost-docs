## Story
**As a** cliente pagante conectando o Instagram pela primeira vez,
**I want** ser avisado antes de conectar que preciso de uma conta Business/Creator, e receber uma mensagem clara se algo der errado,
**so that** eu não trave no onboarding sem entender por quê e desista silenciosamente.

## Contexto / Motivação

Investigação em 2026-07-22 (durante preparação de um beta test) encontrou um gap real no fluxo de onboarding: a API do Instagram (migração de 13/06 para API nativa, sem Facebook Login) só aceita contas profissionais (Business ou Creator) — contas pessoais não têm acesso à API de publicação. Esse é um requisito da própria Meta, não algo que o AutoPost controla ou pode contornar.

Hoje (`frontend/components/onboarding/StepConnectInstagram.tsx`):
- **Nenhum aviso** antes do clique em "Conectar com Instagram" sobre o requisito de conta profissional
- **Nenhum tratamento de erro** no retorno do OAuth (`app/onboarding/page.tsx` só trata `connected=true`) — se o backend falhar, o usuário provavelmente cai numa resposta JSON crua do FastAPI (`app/api/meta.py:meta_callback` levanta `HTTPException` diretamente, sem redirect)

Resultado: um cliente pagante com conta pessoal trava sem explicação e pode desistir sem nunca reportar o problema — pior que um erro visível, porque é silencioso.

Boa notícia para o aviso: converter para Business/Creator é grátis, leva ~1 minuto, e desde a migração de 13/06 não exige mais vincular Página do Facebook.

## Acceptance Criteria

### Frontend — Aviso preventivo
1. **AC1:** `StepConnectInstagram.tsx` exibe, antes do botão "Conectar com Instagram", um texto/nota informando que a conta precisa ser Business ou Creator, com uma frase curta de como converter (Configurações → Conta → Mudar para conta profissional, no app do Instagram)
2. **AC2:** O aviso não bloqueia o fluxo — é informativo, o usuário ainda pode clicar em "Conectar" livremente (não sabemos com certeza se a conta dele já é profissional)

### Backend — Erro amigável no callback
3. **AC3:** `meta_callback()` (`app/api/meta.py`) não deve mais deixar `HTTPException` vazar como JSON cru para o navegador do usuário nos pontos de falha que ocorrem **depois** do redirect da Meta (troca de token, busca de dados do usuário) — deve capturar essas falhas e redirecionar para `{FRONTEND_URL}/onboarding?connected=false&error=<mensagem_curta>`
4. **AC4:** Falhas de state JWT inválido/expirado (que só ocorrem por erro de programação ou CSRF, não por ação normal do usuário) continuam retornando 400 direto — não fazem parte deste fix
5. **AC5:** A mensagem de erro redirecionada deve ser genérica e orientativa (não expor detalhes técnicos da API da Meta) — ex.: "Não foi possível conectar. Confirme que sua conta do Instagram é Business ou Creator e tente novamente."

### Frontend — Tratamento do erro
6. **AC6:** `app/onboarding/page.tsx` trata `?connected=false&error=...` no retorno — exibe a mensagem via `toast` (mesmo padrão já usado para o caso de sucesso) e mantém o usuário na etapa de conexão do Instagram (não avança nem quebra a tela)

### Regressão
7. **AC7:** Fluxo de sucesso (`connected=true&username=...`) continua funcionando exatamente como hoje — nenhuma mudança de comportamento no caminho feliz
8. **AC8:** Testes existentes de `test_meta_oauth.py` continuam passando; testes novos cobrem o caminho de erro do callback (redirect com `error=`) com mock via respx
