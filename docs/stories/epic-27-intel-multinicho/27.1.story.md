## Story
**As a** cliente de um segmento diferente de "Construção civil",
**I want** que o endpoint de inteligência semanal (`GET /insights/weekly`) me entregue o dado do MEU segmento — ou uma resposta honesta de "sem dados" —,
**so that** eu não receba tendências de mercado de outro nicho como se fossem do meu.

## Acceptance Criteria

1. **AC1 — Ler o segmento correto:** `get_weekly_insight` lê o segmento de `current_client.brand_profile['segment']`, NÃO do atributo inexistente `business_segment`.
2. **AC2 — Matching normalizado:** o casamento entre o segmento do cliente e `WeeklyContext.segment` usa `_normalize_segment` (lowercase + sem acento) em ambos os lados — mesmo padrão já usado em `get_best_posting_time`.
3. **AC3 — Sem fallback global enganoso:** quando não há `WeeklyContext` para o segmento do cliente, o endpoint retorna **404 honesto** (mensagem de "ainda não há inteligência para o seu segmento"), em vez de servir o registro mais recente de qualquer segmento.
4. **AC4 — Cliente sem segmento:** cliente com `brand_profile['segment']` vazio/ausente recebe 404 honesto (não recebe dado de outro nicho).
5. **AC5 — Zero regressão para construção civil:** cliente com segmento "Construção civil" (ou variação de grafia como "construcao civil") continua recebendo o `WeeklyContext` correspondente (NFR-4).
6. **AC6 — Isolamento multi-tenant:** nenhum cliente recebe `WeeklyContext` de um segmento que não seja o seu (NFR-5).

    select(WeeklyContext.segment, WeeklyContext.suggested_time)
    .where(WeeklyContext.suggested_time.isnot(None))
    .order_by(desc(WeeklyContext.week_of))
    .limit(20)
)
for row_segment, row_suggested_time in weekly_result.fetchall():
    if _normalize_segment(row_segment) == segment_normalized:
        ...

- L54-59: filtra `WHERE WeeklyContext.segment == "geral"` — nunca casa.
- L63-72: **fallback global** pega o `WeeklyContext` mais recente de QUALQUER segmento — é o que serve construção civil a todo mundo. **Remover.**
